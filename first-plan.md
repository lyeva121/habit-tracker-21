# План работ: трекер привычек «21»

Приложение для iPhone через Safari (PWA). Привычка выработана после 21 выполнения по расписанию подряд; один пропуск запланированного дня — счётчик с нуля. Без аккаунтов, без push, данные хранятся на телефоне.

## Технический выбор (зафиксировано)

| Решение | Что выбрали | Почему |
|---|---|---|
| Тип приложения | Веб-приложение (PWA) | Разработка на Windows, запуск на iPhone через Safari + «На экран Домой». Не нужен Mac и App Store |
| Стек | Vite + React + TypeScript | React хорошо подходит для 5 экранов; TypeScript ловит ошибки ИИ на раннем этапе |
| Хранение данных | localStorage телефона | По ТЗ прогресс живёт на конкретном телефоне, без сервера |
| Тесты логики | Vitest | Логика серий и календаря — самая рискованная часть, её покрываем автотестами |
| Хостинг | GitHub Pages (бесплатный HTTPS) | PWA требует HTTPS; заодно получим git-историю проекта |
| График дневника | Свой SVG | Простая линия, стандартные библиотеки не дают нужную ось «0 … 2×первая запись» |

## Как работать с этим планом (для новичка)

1. Одна задача = один заход к ИИ. Не просите сделать «этап целиком» — мелкие шаги дают меньше ошибок.
2. После каждой задачи: запустили, потыкали руками, сделали commit. Commit — это «сохранение игры», к нему можно вернуться.
3. Задача не сходится с описанием — не тащите дальше, сначала почините.
4. Раз в несколько задач проверяйте приложение на настоящем iPhone (этап 0.4), а не только на компьютере.

## Этап 0. Подготовка окружения

### 0.1 Установить Node.js
- Установить Node.js LTS с nodejs.org (все настройки по умолчанию).
- Проверка: в терминале `node -v` и `npm -v` показывают версии.

### 0.2 Создать каркас проекта
- В папке проекта: `npm create vite@latest . -- --template react-ts`, затем `npm install`.
- Проверка: `npm run dev` открывает страницу в браузере.

### 0.3 Git-репозиторий
- `git init`, первый commit. Создать репозиторий на GitHub, запушить.
- Проверка: файлы видны на GitHub.

### 0.4 Открыть приложение с iPhone
- Запустить дев-сервер видимости для сети: `npm run dev -- --host`, узнать IP компьютера, открыть с iPhone `http://<IP>:5173` (телефон и компьютер в одной Wi-Fi сети).
- Проверка: страница открывается на iPhone. Этот приём будем использовать на каждом этапе.

### 0.5 Настроить тесты
- Добавить Vitest + скрипт `npm test`.
- Проверка: пустой пробный тест проходит (`npm test` зелёный).

## Этап 1. Данные и логика (без интерфейса)

Ядро приложения. Всё — чистые функции + тесты. Здесь важнее всего не торопиться.

### 1.1 Модель данных и хранилище
- Типы: `Habit` (id, название, дни недели, дата старта, время суток, час, флаг дневника, статус active/achieved), `Completion` (id привычки, дата запланированного дня, время отметки, необязательное число дневника).
- Слой хранения: загрузка/сохранение массивов привычек и отметок в localStorage.
- Все даты внутри — строки `YYYY-MM-DD` в **локальном** времени телефона (не UTC!).
- Проверка: юнит-тесты сохранения/загрузки, включая случай «в хранилище пусто».

### 1.2 Движок расписания
- Функции: «запланирован ли день D для привычки» (день недели + не раньше даты старта), «план на день D» (список привычек, сгруппированные по времени суток, отсортированы по часу).
- Проверка: тесты — день не по расписанию, день до старта, все дни по умолчанию.

### 1.3 Движок серий (самая важная задача)
- Серия растёт на 1 за каждый выполненный запланированный день — считаем по логу отметок от даты старта.
- Правило закрытия дня: запланированный день D считается пропущенным **в конце дня D+1**, если отметки за D нет (окно «Вчера» — ровно один день).
- При пропуске: серия обнуляется, создаётся событие «сорванная серия» (дата, на каком счёте оборвалась, id привычки).
- Достигнута 21 подряд → привычка получает статус achieved и выпадает из плана дня.
- Обработка «не открывал приложение неделю»: при запуске проходим все незакрытые дни, регистрируем пропуски и обрывы корректно.
- Проверка: тесты-сценарии — 21 подряд; пропуск в середине; отметка задним числом спасает серию; отметка за позавчера уже невозможна; серия после сбоя растёт заново; несколько пропусков подряд дают один обрыв.

### 1.4 Экпорт/импорт резервной копии
- Кнопки «Экспорт» (скачивается JSON со всеми данными) и «Импорт» (загрузка файла).
- Причина: Safari может стереть данные сайта, а прогресс тереть жалко.
- Проверка: экспорт → очистить хранилище → импорт → всё на месте.

## Этап 3. Экраны (по одному за заход)

### 3.1 Экран «Сегодня»
- План на сегодня, сгруппированный по времени суток; у каждого пункта крупная кнопка «Выполнено».
- Отмеченное уезжает вниз в секцию «Сделано сегодня», сверху только несделанное.
- Круглая диаграмма «N из M» запланированного, заполняется по мере отметок.
- Если план пуст — дружелюбная пустышка («На сегодня ничего не запланировано»).
- Проверка: отметить все — круг полный, всё внизу; перезагрузить страницу — состояние сохранилось.

### 3.2 Экран «Вчера» + красная плашка
- Если у вчерашнего плана есть неотмеченное — в шапке «Сегодня» справа красная плашка «Вчера» с мини-кругом «сколько не сделано».
- Экран «Вчера»: только неотмеченное вчера; кнопка «Выполнено» ставит отметку задним числом — серия продолжается.
- Позавчерашние отметки недоступны: если не отметили, серия уже сорвана.
- Проверка: скриптовый сценарий — вчера отмечено 2 из 3, сегодня видим «1 не сделано», отмечаем, история показывает день выполненным.

### 3.3 Экран «Мои привычки» + создание/редактирование
- Список привычек: название, прогресс «X из 21», полоса выполнения, день недели расписания.
- Секция «Достигнутые» внизу с бейджем 21/21 (после достижения привычка туда).
- Форма привычки: название (обязательно), дни недели (по умолчанию все), дата начала (по умолчанию сегодня), время суток и час (необязательно), переключатель «Вести дневник изменений».
- Редактирование существующей — та же форма. Удаление с подтверждением.
- Проверка: создать привычку на 3 дня в неделю → она появляется в «Сегодня» только в свои дни.

### 3.4 Экран «Дневник»
- Список привычек с включённым дневником; нажал — график и список записей.
- График: свой SVG-линия. X — номер выполнения 1…21, Y — записанное число. Ось Y от 0 до **2×первой записи**: первая точка ровно посередине, рост виден как приближение к верхней границе.
- Список записей под графиком: номер, дата, значение.
- Проверка: значения 10, 12, 18 — первая точка на середине высоты, последняя близко к верху.

### 3.5 Экран «История»
- Выбор привычки → календарь месяца (листается назад), цвета дня: выполнено / пропущено / не запланировано / будущие — пустые.
- Ниже — список сорванных серий этой привычки: дата и счёт, на котором оборвалось.
- Проверка: сценарий с пропуском из 1.3 визуально виден в календаре и в списке обрывов.

### 3.6 Число дневника в «Сегодня»
- Если у привычки включён дневник: при нажатии «Выполнено» сначала показать поле для числа (клавиатура цифровая), затем отметить.
- Число привязывается к отметке и попадает в график дневника.
- Проверка: отметка с числом видна в графике.

## Этап 4. Внешний вид

### 4.1 Дизайн-система
- Светлая спокойная тема: мягкий зелёный — основной (выполнено, прогресс), неглубокий синий — второстепенный, много воздуха, фон почти белый.
- Кнопки и строки — крупные, под палец: минимальная высота нажимаемых элементов 48px.
- Единые отступы, скругления, карточки. Один файл с константами цветов/отступов.
- Проверка: все экраны выдержаны в одном стиле, ничего не мельчит.

### 4.2 Мобильные тонкости Safari
- Viewport без горизонтальной прокрутки; контент не прячется под «челку» (safe-area insets).
- Шрифт в полях ввода ≥16px — иначе Safari зумит страницу при фокусе.
- Проверка на iPhone: ввод в форму не дёргает экран, всё читается одной рукой.

## Этап 5. PWA и запуск на телефоне

### 5.1 Манифест и иконки
- manifest (название «Трекер 21», standalone), apple-touch-icon, тема.
- Проверка: «Поделиться → На экран Домой» ставит иконку, открывается без адресной строки Safari.

### 5.2 Офлайн-режим
- Service worker (vite-plugin-pwa): приложение открывается без интернета.
- Проверка: авиарежим → приложение с домашнего экрана открывается и работает.

### 5.3 Публикация
- Сборка `npm run build`, деплой на GitHub Pages, HTTPS-адрес.
- Проверка: приложение открыто с телефона по публичной ссылке, данные не потерялись при переходе с дев-версии (переносим экспортом/импортом).
